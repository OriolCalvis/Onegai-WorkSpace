ASSUMPTIONS
Canvas 1920×1080. The current build calls init(1280,720); every panel below is given as anchor + offset + size so HudTransform resolves it at any viewport.
Type = BitmapFont stand-in. Real font is a procedural 5×7 monospace, uppercase only. Rendered here at its true metric: scale 2 = 10×14 px cell, scale 3 = 15×21.
Every panel is a HudPanel. No new widget framework is proposed — the editor is composed from Fase 9 widgets so it stays implementable with what exists.
UI copy in English as requested. The recreations in turn 1 keep the Spanish strings verbatim, because that is literally what the code draws.
Blue callouts = the spec layer, not part of the UI. Toggle them off with the A key or the Tweaks panel.
FOUND WHILE RECREATING — SIX REAL DEFECTS
01Status text overflows its panel. Application.cpp line 2 of m_statusText is 34 chars → 340px at scale 2, inside a 280px HudPanel starting 12px in. Clips 72px past the frame.
02Tiles and objects are pixel-identical in the editor. level_editor.cpp draws both through atlas.getUV(); only regions 1 and 2 were ever defineRegion'd, and every object spriteId is 3–6. Everything renders as the same 8×8 checker.
03Enemies and pickups are never drawn in the world. Application::init calls addToQueue() for m_player only. They exist in GameSession and show on the minimap, but the isometric scene never renders them.
04A skill id points at nothing. test_objects.json gives the slime combat.skills = ["golpe_gelatinoso"], but Application registers only "tajo" and "cura" in SkillCatalog. find() returns nullptr and the slime silently falls back to a basic attack.
05playerStart sits on a collision tile. test_level.json starts the player at {1,1}; the CSV in test_map.tmx puts GID 2 there, and GID 2 carries collision=true.
06The command menu panel is four times its content. 248×118 of HudPanel around 80×70 of text.
The editor below is designed so 01, 02 and 04 cannot happen again: text boxes are measured against their panel, every catalog entry shows its sprite binding, and unresolved ids are surfaced in the inspector.
